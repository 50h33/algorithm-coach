# 알고리즘 템플릿

직접 작성한 C++ 템플릿은 `cpp/`, Java 템플릿은 `java/` 아래에 저장합니다.
에이전트는 사용자가 명시적으로 요청한 범위에서 템플릿을 만들거나 이름을 변경하며,
노트 정리 과정에서 템플릿을 자동으로 수정하거나 문제 풀이에 넣지 않습니다.

## Java BFS·DFS

`01`은 BFS, `02`는 DFS이며, 다음 번호로 같은 알고리즘의 변형을 구분합니다.

| 파일 | 용도 |
| --- | --- |
| [01_01_bfs.java](java/01_01_bfs.java) | 기존 격자 BFS |
| [01_02_bfs_adjacency_list.java](java/01_02_bfs_adjacency_list.java) | 인접 리스트 BFS, 이동 비용이 1인 그래프의 최단 거리 |
| [02_01_dfs.java](java/02_01_dfs.java) | 기존 인접 행렬 DFS, 연결 요소 개수 |
| [02_02_dfs_adjacency_list.java](java/02_02_dfs_adjacency_list.java) | 재귀 인접 리스트 DFS, 탐색 경로의 깊이와 트리의 거리 |

새 인접 리스트 템플릿 두 개는 `solution(n, edges, start)` 형태로 사용합니다.
정점 번호는 1부터 n까지이며, 기본 연결은 양방향입니다.
시작점의 거리는 0, 도달할 수 없는 정점은 -1이고, 반환 배열의 0번 인덱스는 사용하지 않습니다.

예를 들어 `n = 5`, `edges = {{1, 2}, {1, 3}, {2, 4}, {4, 5}}`, `start = 1`이면
두 템플릿 모두 `{-1, 0, 1, 1, 2, 3}`을 반환합니다.
이 예시는 트리이므로 두 결과가 같습니다. 일반 그래프에서는 DFS의 결과가 최단 거리라는
보장이 없습니다. 재귀 DFS는 탐색 경로가 매우 길면 스택 한계에 주의해야 합니다.

각 파일은 독립적인 `class Solution` 예제이므로 필요한 파일 하나씩 사용합니다.
