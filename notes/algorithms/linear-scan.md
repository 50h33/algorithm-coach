# 순차 탐색과 카운트 차이

## 두 횟수의 같음을 차이 하나로 표현하기

두 종류의 개별 횟수가 필요하지 않고 같아지는 시점만 필요하다면 차이 하나를 저장할 수 있다.

```text
balance = 첫 번째 종류의 개수 - 두 번째 종류의 개수
```

첫 번째 종류를 읽으면 1을 더하고, 두 번째 종류를 읽으면 1을 뺀다.
`balance == 0`이면 두 횟수가 같다.

```java
int balance = 0;
balance++; // 첫 번째 종류: 차이 1
balance--; // 두 번째 종류: 차이 0, 두 횟수가 같음
```

차이가 0이라는 정보만으로 각 종류가 몇 개였는지는 알 수 없다.
두 횟수 자체가 필요한 문제에서는 각각의 카운트도 유지해야 한다.

## 구간이 시작될 때 개수 세기

입력을 연속된 구간으로 나누고 모든 문자가 정확히 한 구간에 포함되며,
끝에 남은 미완성 구간도 한 개로 인정한다면 구간의 시작 시점에 개수를 셀 수 있다.

1. 새 구간의 첫 문자를 읽을 때 개수를 1 증가시키고 그 구간의 기준 문자를 정한다.
2. 문자를 읽으며 기준 문자와 같은 문자에는 1을 더하고, 다른 문자에는 1을 뺀다.
3. 차이가 0이 되어 구간이 끝나면, 다음 문자가 있을 때 새 구간을 시작한다.

이 방식에서는 첫 문자가 항상 기준 문자와 같으므로 새 구간을 시작한 직후 차이는 1이다.
입력을 다 읽은 뒤 다음 문자가 없다면 새 구간도 시작하지 않는다.

예를 들어 `"pqp"`를 위 규칙으로 읽는 과정은 다음과 같다.

| 현재 문자 | 동작 | 처리 후 차이 | 구간 개수 |
| --- | --- | ---: | ---: |
| 첫 `p` | 새 구간 시작, 기준과 같음 | 1 | 1 |
| `q` | 기준과 다름, 두 횟수가 같아져 구간 종료 | 0 | 1 |
| 마지막 `p` | 새 구간 시작, 기준과 같음 | 1 | 2 |

마지막 구간은 종료 조건을 만족하지 못했지만 시작할 때 이미 개수에 포함됐다.
따라서 이 방식에 마지막 구간을 세는 증가 연산을 다시 추가하면 중복 집계가 된다.
종료 조건을 만족한 구간만 인정하는 문제라면 같은 방식으로 세어서는 안 된다.

## 반복문과 재귀의 처리 비용

각 문자를 한 번씩 읽고 상수 시간의 연산만 하면 시간 복잡도는 `O(n)`이다.
기준 문자, 차이, 구간 개수 등 고정된 수의 변수만 쓰면 추가 공간은 `O(1)`이다.

재귀도 각 문자를 한 번만 처리하면 시간은 `O(n)`일 수 있지만, 호출 깊이에 따른 스택 공간이 든다.
반복문으로 순차 처리하면 하위 호출에 맡긴 부분을 다시 순회하는 제어 흐름도 피할 수 있다.
재귀의 처리 범위는 [반환값과 재귀 호출](../java/recursion-and-return.md)을 참고한다.
