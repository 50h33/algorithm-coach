# 단조 스택

## 아직 답을 찾지 못한 인덱스를 보관하기

각 원소의 오른쪽에서 처음으로 더 큰 값을 찾을 때, 위치마다 뒤쪽을 다시 탐색하면
내림차순 배열에서 `(n - 1) + (n - 2) + ... + 1`번 비교하게 되어 시간이 `O(n²)`이다.
큰 값을 찾았을 때 탐색을 중단해도, 큰 값이 없는 경우의 반복 탐색은 남는다.

왼쪽부터 읽으며 **아직 오른쪽의 더 큰 값을 만나지 못한 인덱스**를 스택에 저장하면
새 원소 하나로 기다리던 여러 위치의 답을 결정할 수 있다.

- 현재 값이 스택 맨 위 인덱스의 값보다 크면, 그 인덱스를 꺼내 현재 값을 답으로 기록한다.
- 꺼낸 뒤 새로 드러난 맨 위도 현재 값보다 작으면 계속 처리한다.
- 스택이 비었거나 맨 위의 값이 현재 값 이상이면 멈추고 현재 인덱스를 넣는다.
- 모든 입력을 읽은 뒤 남은 인덱스에는 오른쪽의 더 큰 값이 없다. 결과 규칙에 맞는 표시를 남긴다.

스택에는 인덱스가 들어간다. 값 비교와 결과 위치 지정의 차이는
[스택에 값 대신 인덱스 저장하기](../java/stack-and-queue.md#스택에-값-대신-인덱스-저장하기)를 참고한다.

## 현재 값 하나가 여러 답을 정할 수 있다

`[4, 7, 7, 9]`를 읽는 예다. 아래 스택 표시는 왼쪽이 바닥, 오른쪽이 맨 위이며,
값의 흐름을 보여 주기 위해 `인덱스:값`으로 적었다.

| 현재 인덱스와 값 | 답을 결정하는 동작 | 처리 후 스택 |
| --- | --- | --- |
| `0:4` | 기다릴 인덱스 0을 넣음 | `[0:4]` |
| `1:7` | 인덱스 0을 꺼내 그 답을 7로 기록 | `[1:7]` |
| `2:7` | 같은 값은 더 큰 값이 아니므로 꺼내지 않음 | `[1:7, 2:7]` |
| `3:9` | 인덱스 2, 1을 차례로 꺼내 각각의 답을 9로 기록 | `[3:9]` |

마지막 값 9를 처리할 때 `if`로 하나만 꺼내면 인덱스 1의 답을 놓친다.
현재 값으로 해결할 수 있는 원소가 남아 있는 동안 `while`로 반복해야 한다.
반복 조건은 빈 스택 여부를 먼저 확인한 뒤 맨 위의 값을 비교한다.
관련 문법은 [조건문과 반복문](../java/control-flow.md)을 참고한다.

## 스택의 순서와 가장 가까운 값이 보장되는 이유

스택의 인덱스는 바닥에서 맨 위로 갈수록 커진다. 해당 인덱스의 값은 같은 값도 허용하며
비증가 순서로 유지된다. 예를 들어 아래에서 위로 `[9, 7, 7, 4]`처럼 쌓일 수 있다.
이처럼 값의 순서가 한 방향으로 유지되는 스택을 단조 스택이라고 한다.

현재 값보다 작은 맨 위 원소를 모두 꺼낸 뒤 현재 인덱스를 넣으므로 이 순서가 유지된다.
맨 위의 값이 현재 값 이상이면 그 아래 값들도 현재 값 이상이어서 더 꺼낼 필요가 없다.
엄격하게 더 큰 값을 찾는 경우 같은 값은 답이 될 수 없으므로 비교에 등호를 포함하지 않는다.

인덱스가 아직 스택에 남아 있다는 것은 그 위치 이후 지금까지 더 큰 값을 만나지 못했다는 뜻이다.
왼쪽부터 순서대로 읽다가 처음으로 더 큰 현재 값을 만나 꺼내므로, 그 값은 오른쪽에서
가장 가까운 더 큰 값이다.

## 중첩 반복문이어도 전체 시간은 O(n)

현재 값 하나가 여러 원소를 꺼낼 수 있지만, 각 인덱스는 전체 실행에서 한 번 들어가고
최대 한 번 나온다. 한 번 꺼낸 인덱스를 다시 넣지 않으므로 모든 `pop()`의 횟수를 합쳐도
최대 n번이다. `ArrayDeque`의 삽입은 분할 상환 `O(1)`이고 맨 위 조회·제거는 `O(1)`이다.

따라서 입력 순회와 스택 처리를 합친 시간은 `O(n)`이다. 남은 인덱스를 마지막에 꺼내며
결과를 채우는 작업까지 포함해도 `O(n)`이고, 내림차순 입력에서는 n개가 모두 쌓일 수 있어
스택의 추가 공간은 `O(n)`이다. 결과 배열도 `O(n)` 공간을 사용한다.
