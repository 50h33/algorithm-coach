# BFS와 거리 제한 탐색

## 가까운 칸부터 확인하기

BFS는 큐를 이용해 출발점에서 가까운 정점부터 탐색한다. 모든 이동 비용이 같으면
처음 발견한 경로의 이동 횟수가 최단 거리다. 연결 정보의 표현은
[그래프 인접 리스트](../java/adjacency-list.md)를 참고한다.

출발점에서 최대 K번 이동해서 도달할 수 있는 대상을 찾을 때 BFS를 사용할 수 있다.
DFS도 이동 횟수를 제한하면 가능하지만, 가까운 순서로 방문하지 않으므로
먼 경로에서 먼저 방문했다는 이유만으로 더 짧은 경로의 탐색을 막지 않도록 주의해야 한다.

격자에서는 상하좌우의 유효한 칸을 이웃으로 보고, 벽이나 파티션은 이동할 수 없는 칸으로 처리한다.
예를 들어 아래 격자에서 S는 출발점, T는 목표, O는 빈칸, X는 벽이다.

```text
S O
X T
```

아래쪽은 막혀 있어도 오른쪽, 아래쪽 순서로 두 번 이동하면 T에 도달한다.
대각선의 두 칸 사이에는 두 개의 2회 이동 경로가 있으며, 그중 하나라도 열려 있으면 도달할 수 있다.
맨해튼 거리는 `|행 차이| + |열 차이|`이고, 장애물을 피해 실제로 이동해야 하는 거리는 더 길거나
경로가 없을 수 있다. 좌표 거리 조건과 장애물을 고려한 도달 가능성을 구분한다.

## dist로 거리와 방문 여부 함께 관리하기

- `dist[y][x] == -1`: 아직 발견하지 않은 칸
- `dist[y][x] == 0`: 출발점
- `dist[y][x] > 0`: 출발점에서 해당 칸까지의 최소 이동 횟수

배열을 -1로 채우는 문법은 [Arrays.fill](../java/list-and-array.md#arraysfill로-배열-초기화하기)을 참고한다.
출발점은 큐에 넣기 전에 거리 0으로 표시한다. 새 칸도 큐에 넣을 때 거리를 기록해야
여러 경로에서 같은 칸을 중복으로 큐에 넣지 않는다.

```java
// ny, nx의 범위와 장애물 여부를 먼저 검사한 뒤 사용하는 부분 코드
if (dist[ny][nx] != -1) continue;
dist[ny][nx] = dist[y][x] + 1;
q.offer(new int[]{ny, nx});
```

거리만 기록하고 큐에 넣지 않으면 그 칸의 이웃은 탐색하지 않는다.
반대로 방문 검사를 없애면 인접한 두 칸을 `A → B → A → B`처럼 계속 큐에 넣고
거리를 덮어쓸 수 있다. 도달할 수 없는 목표를 찾는 탐색이 끝나지 않을 수도 있다.

독립적인 출발점마다 탐색한다면 거리 배열 전체를 -1로 초기화하고 새 출발점만 0으로 설정한다.
큐만 비우거나 새 출발점의 거리만 바꾸면 이전 탐색의 방문 표시가 남아 이동을 막는다.
각 BFS 호출 안에서 큐와 거리 배열을 새로 만들면 탐색 사이에 상태가 섞이지 않는다.
출발점 자체를 목표로 세면 안 되는 경우에는 거리 0을 목표 검사에서 제외한다.

## 출발점, 현재 칸, 다음 칸 구분하기

| 좌표 | 역할 | 확인할 정보 |
| --- | --- | --- |
| `sy, sx` | 출발점 | 최초 거리 0 설정 |
| `y, x` | 큐에서 꺼낸 현재 칸 | 현재 거리와 목표 여부 |
| `ny, nx` | 이동하려는 다음 칸 | 범위, 장애물, 방문 여부 |

다음 칸이 벽인지 검사할 때는 `grid[ny][nx]`를 본다.
행 수가 n, 열 수가 m인 직사각형 격자의 범위 검사는 다음과 같다.

```java
if (ny < 0 || ny >= n || nx < 0 || nx >= m) continue;
```

유효한 열 인덱스는 `0 <= nx && nx < m`이다. 제외 조건에 `nx >= 0`을 쓰면
정상적인 열까지 모두 제외된다. 범위를 확인한 다음 배열에 접근한다.

탐색 범위를 제한할 때는 `dist[y][x]`를 본다. 출발점의 거리는 항상 0이므로
출발점 거리를 비교해서는 탐색 깊이를 제한할 수 없다.

## 경로마다 달라지는 상태 구분하기

BFS의 큐에는 서로 다른 경로로 도착한 위치들이 섞여 있다.
한 경로에서 스위치를 켰다고 해서 다른 경로도 스위치를 거쳤다는 뜻은 아니다.
탐색 전체가 공유하는 boolean 하나로 경로별 스위치 상태를 나타내면 잘못된 경로를 허용할 수 있다.

한 번의 BFS에서 이런 조건을 처리하려면 위치와 상태를 함께 탐색 단위로 삼는다.
예를 들어 큐에 `(y, x, 스위치 상태)`를 넣고 방문 기록도 `visited[y][x][state]`로 구분한다.
같은 칸이라도 스위치를 켜기 전과 후는 별개 상태이므로 각각 방문할 수 있다.
재방문을 무조건 허용하는 것이 아니라, 같은 상태의 중복 방문을 막는 방식이다.

## 필수 경유지가 있을 때 탐색 나누기

고정된 경유지 M을 거쳐 목표 T로 가야 하고, 각 구간의 이동 가능 여부가 이전 경로에
의존하지 않으며 칸을 다시 지날 수 있다면 `S → M`, `M → T`를 독립적으로 탐색할 수 있다.
모든 유효한 경로는 M을 거치므로 각 구간의 최단거리 합이 전체 최단거리다.
목표 칸을 미리 지나도 되는 규칙이라면 첫 탐색에서 목표 칸을 벽처럼 막지 않는다.

```text
첫 구간 거리 = S에서 M까지의 최단거리
첫 구간에 도달할 수 없으면 -1 반환
둘째 구간 거리 = M에서 T까지의 최단거리 (방문 기록을 새로 시작)
둘째 구간에 도달할 수 없으면 -1 반환
두 거리의 합 반환
```

예를 들어 구간별 거리가 3과 5이면 총 거리는 8이다. 두 번째 거리만 반환하면 첫 구간이 빠진다.
첫 탐색에서 경유지를 찾지 못했다면 좌표 변수의 초기값으로 다음 탐색을 시작하지 않는다.
실패 여부는 거리의 -1 또는 명시적인 발견 여부로 판단하며, `(0, 0)` 자체를 실패 표시로 쓰지 않는다.

각 탐색 안에서는 중복 방문을 막지만 두 탐색 사이에는 방문 기록을 공유하지 않는다.
따라서 두 번째 탐색에서 첫 구간에 지나온 길을 되돌아갈 수 있다.
n × m 격자의 상하좌우 BFS를 두 번 수행해도 시간과 추가 공간 복잡도는 각각 `O(nm)`이다.

## 거리 K에서는 검사하고 확장은 멈추기

거리 K인 칸도 검사 대상에 포함하되 그 이웃을 큐에 추가하지 않는다.
큐에서 현재 칸을 꺼낸 뒤 목표 여부를 먼저 확인하고, 다음 조건으로 확장을 막는다.

```java
// 현재 칸의 목표 여부를 검사한 뒤
if (dist[y][x] == limit) continue;
// 이 아래에서 이웃 칸 탐색
```

거리 K인 칸에서 확장한 뒤 K + 1인 칸을 꺼내 버리는 방식도 가능하지만,
확장 전에 멈추면 불필요한 큐 삽입을 줄일 수 있다.
