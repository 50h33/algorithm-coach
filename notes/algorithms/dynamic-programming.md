# 동적 계획법의 상태 전이와 계산 순서

## 상태가 나타내는 값 정하기

동적 계획법(DP)은 작은 상태의 계산 결과를 저장해 다음 상태를 계산하는 방법이다.
행마다 한 칸을 선택하며 점수를 누적한다면 다음과 같이 상태를 정의할 수 있다.

```text
dp[y][x] = y행의 x열을 선택하고 끝나는 경로 중 최대 누적 점수
```

`dp[y][x]`는 해당 칸의 점수만 저장하는 값도, y행 전체에서의 최댓값도 아니다.
같은 칸에 도착한 뒤 가능한 선택이 이전 경로와 무관하게 같다면,
그 칸까지의 경로 중 누적 점수가 가장 큰 것만 남겨도 된다.

## 이동 조건을 상태 전이에 그대로 반영하기

격자 모양으로 입력된다고 해서 이동이 상하좌우나 인접 대각선으로 제한되는 것은 아니다.
다음 행에서 같은 열을 선택할 수 없다는 조건이라면, 현재 열과 다른 모든 열이 후보가 된다.
예를 들어 4개 열 중 0번 열을 선택했다면 다음 행에서는 1, 2, 3번 열을 모두 선택할 수 있다.

이때 `dx = {-1, 1}`처럼 열 차이를 제한하면 허용되는 경로 일부를 빠뜨린다.
열을 직접 순회하고 같은 열만 제외하면 조건을 명확하게 표현할 수 있다.

```java
// y행의 누적 점수가 모두 확정되었고, 다음 행이 존재할 때의 부분 코드
for (int nextX = 0; nextX < columns; nextX++) {
    if (nextX == x) continue;
    dp[y + 1][nextX] = Math.max(
        dp[y + 1][nextX], dp[y][x] + score[y + 1][nextX]
    );
}
```

위처럼 최댓값을 누적할 때 초기값도 확인해야 한다.
모든 칸에 도달 가능하고 점수가 양수인 경우에는 0으로 초기화할 수 있지만,
음수 점수나 도달 불가능한 상태가 있다면 이를 구분할 초기값과 별도 검사가 필요하다.
[최댓값 초기화](../java/control-flow.md#빈-컬렉션과-최댓값-초기화)도 참고한다.

## 의존하는 상태를 먼저 확정하기

다음 행의 값이 현재 행의 여러 열에 의존한다면, 현재 행 전체를 계산한 뒤 다음 행을 처리해야 한다.
행 `y`를 바깥 반복문, 열 `x`를 안쪽 반복문에 두는 이유는 이 의존 관계 때문이다.

열을 바깥 반복문에 두고 한 열씩 끝까지 내려가면, 어떤 칸에서 다음 행으로 값을 전달한 뒤
그 칸의 누적 점수가 다른 열에서 뒤늦게 갱신될 수 있다.
이미 처리한 다음 행에는 이 개선된 값이 자동으로 다시 전달되지 않는다.

```text
어떤 칸의 누적 점수가 9일 때, 다음 칸의 점수 4를 더해 13을 전달
나중에 원래 칸의 누적 점수가 12로 개선됨
다음 칸을 다시 갱신하지 않으면 16이 반영되지 않음
```

핵심은 항상 행부터 순회한다는 규칙이 아니라, 값을 읽기 전에 그 값의 계산이 끝나 있어야 한다는 것이다.
다른 상태 정의나 점화식에서는 필요한 순회 순서도 달라질 수 있다.

## 시작 상태를 모두 초기화한 뒤 전이하기

어느 열에서든 시작할 수 있다면 첫 행의 각 상태는 그 칸의 점수다.

```java
for (int x = 0; x < columns; x++) {
    dp[0][x] = score[0][x];
}
// 첫 행 전체를 초기화한 뒤, 행 순서대로 다음 상태를 계산한다.
```

현재 칸에서 다음 행으로 값을 전달하는 방식은 `y + 1 < rows`인 동안 처리한다.
반대로 이전 행의 값으로 현재 행을 계산하는 방식은 `y = 1`부터 시작한다.
두 방식 모두 같은 상태 전이를 표현할 수 있으며, 첫 행 초기화와 반복 범위를 구분하면 된다.
