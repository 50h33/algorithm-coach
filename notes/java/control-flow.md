# Java 조건문과 반복문의 처리 순서

## if와 else if는 처음 참인 분기 하나만 실행한다

`if` 조건이 참이면 같은 연결에 있는 `else if`는 검사하지 않는다.
두 조건이 동시에 참일 수 있다면, 어느 조건을 먼저 둘지가 결과에 영향을 준다.

```java
boolean lastPosition = true;
boolean boundaryReady = true;
int count = 0;

if (lastPosition) {
    count += 1;
} else if (boundaryReady) {
    count += 2;
}
// count는 1: 두 조건이 참이어도 두 번째 분기는 실행하지 않음
```

독립된 `if` 두 개라면 두 조건이 모두 참일 때 두 블록 모두 실행될 수 있다.
분기 순서를 바꾸는 것과 `else if`를 별도 `if`로 바꾸는 것은 다른 동작이다.

## if는 한 번 처리하고 while은 조건이 유지되는 동안 반복한다

`if`는 해당 지점에서 조건을 한 번 검사한다. 블록 안에서 상태를 바꾼 뒤에도 조건이 참이라고 해서
같은 블록을 다시 실행하지 않는다. `while`은 블록 실행 후 조건을 다시 검사한다.

```java
int once = 3;
if (once > 0) {
    once--;
}
// once는 2

int repeated = 3;
while (repeated > 0) {
    repeated--;
}
// repeated는 0
```

현재 입력 하나로 대기 중인 여러 원소를 처리해야 한다면, 하나를 처리한 뒤에도 조건을 확인하는
반복이 필요하다. 스택에서 여러 원소를 꺼내는 예는 [단조 스택](../algorithms/monotonic-stack.md)을 참고한다.
반복 중 스택이 빌 수 있으므로, [스택과 큐](stack-and-queue.md)에 설명된 빈 상태 확인도 필요하다.

## continue와 break의 차이

`continue`는 현재 회차의 남은 본문만 건너뛴다. 일반적인 `for`문에서는 증감식과 조건 검사를
거쳐 다음 회차로 넘어가므로 반복 자체는 계속된다. `break`는 가장 가까운 반복문을 끝낸다.

```java
for (int i = 0; i < 4; i++) {
    if (i == 1) continue;
    System.out.print(i + " ");
}
// 출력: 0 2 3

for (int i = 0; i < 4; i++) {
    if (i == 1) break;
    System.out.print(i + " ");
}
// 출력: 0
```

답을 찾은 뒤 `if (found) continue;`로 본문을 생략해도 남은 반복 회차는 진행한다.
탐색을 마쳤다면 `break`로 종료할 수 있지만, 답을 찾지 못하는 입력에서는 끝까지 탐색하므로
그 변경만으로 최악의 시간 복잡도가 줄어드는 것은 아니다.

## 조건을 확인하는 시점의 상태를 해석하기

문자를 센 뒤 조건을 확인하는지, 조건을 확인한 뒤 문자를 세는지 구분한다.
현재 문자 처리 전에 검사하는 코드에서 카운트는 이전 문자까지의 상태다.

예를 들어 첫 글자를 미리 세고, 이후 반복문에서 조건을 먼저 검사한다면:

| 시점 | 카운트에 포함된 범위 |
| --- | --- |
| `i`번째 문자를 세기 전 | 시작 위치부터 `i - 1`까지 |
| `i`번째 문자를 센 후 | 시작 위치부터 `i`까지 |

`"pqp"`를 첫 문자와 같은 문자 수 / 다른 문자 수로 세면, 마지막 `p`를 읽기 직전에는
`"pq"`에 대한 두 횟수가 각각 1이다. 이미 읽은 `"pq"`를 분리할 조건이 성립한다면,
마지막 위치라는 이유만으로 전체를 한 구간으로 처리해서는 안 된다.
이 구조에서는 이미 성립한 분리 조건을 먼저 처리해야 한다.

이때 다음 구간은 아직 읽지 않은 현재 위치 `i`부터 시작한다.
현재 문자까지 센 뒤에 분리 조건을 확인하는 구조라면, 다음 위치는 `i + 1`이다.
다음 인덱스는 카운트가 어디까지 반영되었는지에 맞춰 정한다.

## 반복문은 한 번도 실행되지 않을 수 있다

```java
String s = "x";
int start = 0;
int visits = 0;

for (int i = start + 1; i < s.length(); i++) {
    visits++;
}
// i는 1에서 시작하지만 1 < 1이 거짓이므로 visits는 0
```

반복문 안에 마지막 인덱스 조건을 넣어도, 반복문 자체가 실행되지 않으면 그 조건은 검사하지 않는다.
처리해야 할 한 글자가 남았다는 사실과 반복문에 진입할 수 있는지는 별개다.

### 빈 컬렉션과 최댓값 초기화

원소가 없는 배열이나 컬렉션의 향상된 for문도 한 번도 실행되지 않는다.
빈 Map의 `entrySet()`이나 `values()`를 순회하는 경우도 같다.
반복문 안에서만 결과를 갱신한다면 빈 경우에는 초기값이 그대로 남는다.

```java
int[] counts = {};
int maximum = 0;
for (int count : counts) {
    maximum = Math.max(maximum, count);
}
// 반복문을 실행하지 않으므로 maximum은 0
```

개수처럼 값이 모두 0 이상이고, 기록이 없을 때의 결과를 0으로 정의한다면 초기값을 0으로 둔다.
초기값을 -1로 두면 빈 경우에 -1이 그대로 반환된다.
빈 데이터의 수학적 최댓값이 0이라는 뜻은 아니며, 문제에서 요구하는 빈 경우의 결과를 반영한 것이다.
음수도 가능한 값의 최댓값을 찾을 때는 0으로 시작하면 잘못된 결과가 나올 수 있으므로,
빈 경우를 별도로 처리하고 첫 원소로 초기화하는 등의 방법을 사용한다.

## 마지막 인덱스와 마지막 구간은 다르다

마지막 위치에 도달했을 때 그 앞의 구간이 이미 완성되었을 수도 있고,
끝까지 읽었는데도 구간 종료 조건을 만족하지 못했을 수도 있다.
남은 부분도 한 구간으로 세는 규칙이라면 해당 경우까지 집계해야 한다.

반복문 종료 후 남은 구간을 처리할 때는 실제로 아직 세지 않은 부분이 있는지 확인한다.
무조건 개수를 1 더하면 마지막 위치에서 이미 완성되어 집계된 구간까지 다시 셀 수 있다.
다른 방법으로는 [구간 시작 시 집계](../algorithms/linear-scan.md)를 사용할 수 있다.

## 비교 연산자는 경계값의 포함 여부로 정하기

`>`는 같은 값을 제외하고, `>=`는 같은 값도 포함한다.
기간이나 한도를 비교할 때는 정확히 경계에 도달한 순간을 포함하는지 먼저 확인한다.

예를 들어 유효기간이 지난 당일부터 만료되는 규칙이면 다음과 같이 비교한다.

```java
int elapsedDays = 84;
int validDays = 84;
boolean expired = elapsedDays >= validDays; // true
```

| 경과 일수 | 84일에 도달하면 만료되는 규칙 |
| --- | --- |
| 83 | 아직 유효 |
| 84 | 만료 |
| 85 | 만료 |

매달 28일로 정의된 달력에서는 3개월이 `3 * 28 = 84`일이다.
이 규칙에서 2월 19일부터 5월 19일까지는 정확히 84일이므로 만료 대상이다.
실제 달력에 모든 달이 28일이라는 계산을 적용해서는 안 된다.
경계 당일까지 유효한 별도의 규칙이라면 `>`가 맞으므로 문제의 포함 조건에 맞춰 선택한다.
