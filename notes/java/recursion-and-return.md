# Java 반환값과 재귀 호출

## 메서드 호출과 반환값 저장은 별개다

메서드가 값을 반환해도 호출한 쪽의 지역 변수에 자동으로 저장되지는 않는다.
반환값을 계산에 쓰려면 대입하거나 더하거나, 그대로 반환해야 한다.

```java
static int countItems() {
    return 2;
}
```

위 메서드를 호출하는 코드 조각을 비교하면 다음과 같다.

```java
int answer = 0;
countItems();           // 반환값 2를 사용하지 않음: answer는 0
answer = countItems();  // 반환값으로 대입: answer는 2
answer += countItems(); // 반환값을 더함: answer는 4
```

`return answer;`는 그 시점의 answer 값을 반환한다. 앞서 버린 반환값을 찾아 더하거나,
아직 처리하지 않은 항목을 자동으로 계산하지 않는다.

## 재귀 호출마다 지역 변수가 따로 생긴다

같은 메서드를 재귀 호출하더라도 각 호출의 매개변수와 지역 변수는 별개다.
하위 호출의 지역 변수가 바뀌어도 상위 호출의 같은 이름 변수는 직접 바뀌지 않는다.
상위 호출은 하위 호출의 반환값을 받아 자신의 계산에 합칠 수 있다.

```java
// n >= 0, 작은 n을 전제로 한 설명용 예제
static int sumTo(int n) {
    if (n == 0) {
        return 0;
    }

    int cur = n;
    cur += sumTo(n - 1);
    return cur;
}
```

`sumTo(3)`은 각 호출이 반환할 때 다음 순서로 합쳐진다.

| 현재 호출 | 이 호출의 초기 cur | 하위 호출의 반환값 | 합친 뒤 반환값 |
| --- | ---: | ---: | ---: |
| `sumTo(1)` | 1 | 0 | 1 |
| `sumTo(2)` | 2 | 1 | 3 |
| `sumTo(3)` | 3 | 3 | 6 |

## 하위 호출의 return 이후에도 상위 호출은 계속 실행된다

`cur += sumTo(n - 1);`은 하위 호출이 끝날 때까지 기다렸다가 반환값을 cur에 더하고,
그다음 문장으로 진행한다. 재귀 호출 자체가 상위 메서드나 상위 반복문을 종료하지는 않는다.

- `return`은 현재 메서드 호출을 끝내고 호출한 곳으로 돌아간다.
- 반복문에 적용한 `break`는 그 반복문만 끝내며, 메서드의 나머지 코드는 계속 실행된다.

## 재귀에 맡긴 처리 범위를 다시 처리하지 않기

구간 개수를 재귀로 센다면 각 호출이 맡는 범위를 먼저 정한다.
예를 들어 한 호출이 현재 구간 1개를 확정하고 **남은 범위 전체**를 하위 호출에 맡겼다면,
반환값은 `현재 구간 1개 + 남은 범위의 구간 수`다.
그 결과를 합친 뒤 같은 남은 범위를 현재 반복문에서 또 세면 중복 집계한다.
이 구조에서는 결과를 합친 시점에 현재 호출을 종료할 수 있다.

`cur++`만 수행하는 분기와 `cur++` 후 하위 호출의 반환값까지 더하는 분기는 결과가 다르다.
남은 범위의 결과가 1이면 전자는 1, 후자는 `1 + 1 = 2`를 계산한다.

모든 재귀 호출 뒤에 곧바로 반환해야 한다는 뜻은 아니다. 여러 하위 범위를 각각 처리해야 하는
탐색에서는 다음 호출을 계속해야 한다. 종료 여부는 하위 호출에 맡긴 범위로 결정한다.

재귀의 종료 조건은 반복문이 실행되지 않는 작은 입력에서도 반환값을 정의해야 한다.
조건 검사와 반복문의 실행 범위는 [조건문과 반복문의 처리 순서](control-flow.md)를 참고한다.

## 다음에 처리할 인덱스와 종료 시점

배열을 순서대로 처리하는 재귀에서 `idx`를 **다음에 처리할 원소의 인덱스**로 정했다면,
현재 호출에는 인덱스 `0`부터 `idx - 1`까지의 처리 결과가 반영되어 있다.
길이가 `n`인 배열에서 각 상태의 의미는 다음과 같다.

| 상태 | 처리한 원소 수 | 남은 처리 |
| --- | ---: | --- |
| `idx == 0` | 0개 | 모든 원소 |
| `idx == n - 1` | n - 1개 | 마지막 원소 1개 |
| `idx == n` | n개 | 없음 |

예를 들어 길이가 3이면 `idx == 2`에서 마지막 원소를 처리하고,
`idx == 3`으로 호출했을 때 전체 처리가 끝난다.
마지막 원소의 인덱스와 모든 원소를 처리한 시점을 구분해야 한다.

`idx == n`은 배열 접근에는 사용할 수 없지만, 재귀의 완료 상태로는 사용할 수 있다.
따라서 종료 조건을 `numbers[idx]`에 접근하는 코드보다 먼저 검사한다.

## 모든 선택을 마친 뒤 정답 판정하기

모든 원소에 대한 선택을 완료해야 하는 경우의 수 탐색에서는,
중간 결과가 목표와 같아졌다는 이유만으로 정답 1개를 반환하면 안 된다.
남은 선택에 따라 최종 결과가 달라지거나 여러 정답으로 이어질 수 있기 때문이다.

예를 들어 현재 합과 목표가 모두 3이고, 아직 처리할 숫자 1 두 개가 남았다면
`+1-1`과 `-1+1`의 두 선택이 최종 합 3을 만든다.
중간 합이 3일 때 바로 `1`을 반환하면 서로 다른 두 완성 경로를 하나로 세게 된다.

`idx`가 다음에 처리할 인덱스이고 매번 1씩 증가한다면, 완료 상태의 판정은 다음처럼 묶을 수 있다.

```java
if (idx == numbers.length) {
    return total == target ? 1 : 0;
}
```

모든 원소를 처리한 뒤 조건을 만족하면 1, 만족하지 않으면 0을 반환하고,
아직 원소가 남았다면 다음 선택을 탐색한다. 서로 다른 선택에 대한 하위 호출의 반환값을
더하면 완성된 정답 경로의 개수가 된다.

완료 상태에서 무조건 `0`을 반환하는 조건을 정답 검사보다 먼저 두면,
정답인 경로도 검사하지 못하고 종료된다. 완료 여부와 성공 여부를 함께 처리하면 이를 피하기 쉽다.
